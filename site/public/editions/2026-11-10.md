## Today in 90 seconds

- **The model market split further at both ends.** Anthropic released Claude Fable 5.2 and Mythos 5.2 for unusually hard, open-ended technical work, while Meta released Muse Ember for the many cheap, repeated steps inside agents. Anthropic prices Fable at $8 per million input tokens and $40 per million output tokens; Meta prices Ember below 200K context at $0.10 and $0.50 respectively. Both companies’ benchmark and scientific-result claims remain vendor-reported rather than independent reproductions.

- **Two AI-infrastructure flaws moved from “serious” to “known exploited.”** CISA’s November 9 catalog update added GPUStack’s unauthenticated loopback-trust bypass and OpenSSH’s password-authentication bypass on Linux systems using musl libc without PAM. GPUStack before 2.2.0 can expose administrator control and worker-host code execution; the OpenSSH issue is fixed in portable OpenSSH 10.6p2 and does not apply to ordinary glibc-plus-PAM builds.

- **The developer-tool signal was unusually practical.** DBDelve 0.7.1 made ODBC result grids safely editable; RuView turns Wi-Fi CSI into experimental room sensing; GBrain offers provenance-aware memory shared across agents; HA-MCP lets an assistant configure and debug Home Assistant; and current Codex commits improve deferred-MCP discovery and model catalogs behind OAuth gateways. Each has a sharp boundary—unsigned builds, special hardware, sensitive-memory handling, administrator credentials, or unreleased upstream code.

## Tech & AI

### Anthropic releases Claude Fable 5.2 and Mythos 5.2

Anthropic says Fable 5.2 and Mythos 5.2 are the same underlying model with different safeguards and access paths. Fable is generally available, including through AWS, Google Cloud and Microsoft Azure; Mythos is reserved for verified cybersecurity and life-sciences users. Developers can call Fable as `claude-fable-5-2`. Anthropic positions the pair above Opus 5.5 for ambitious, open-ended engineering and scientific work, while still recommending Opus 5.5 as the everyday starting point.

The practical changes are speed and price as much as benchmark position. Anthropic reports up to 30% faster output than Fable/Mythos 5.1 at $8 per million input tokens and $40 per million output tokens. An optional fast mode claims up to 2.5× generation speed for twice that price. The release also supports “Advisor” and “Orchestrator” patterns in which smaller models consult Fable or receive delegated work from it.

The headline science demonstrations—formalizing Fermat’s Last Theorem in 30 hours, solving two open black-hole physics problems and designing three working electronic devices—come from Anthropic’s prerelease testing. They are interesting capability evidence, not independent confirmation that the model has generally solved those fields. Anthropic also says it tested sandbox escape, distillation resistance, alignment and biological/cyber misuse; the linked system card is the right place to inspect the methods before treating a benchmark table as a deployment guarantee. [Official announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2) · [Model overview](https://platform.claude.com/docs/en/models/fable-5-2/overview)

### Meta launches Muse Ember for high-volume agent execution

Muse Ember 1.0 is Meta’s smallest reasoning model for repeated agent work: tool calls, routing, extraction, coding subtasks and long-document processing. It supports the Responses API, a one-million-token context window and up to 512K output tokens. Meta’s standard under-200K-context list price is $0.10 per million input tokens, $0.004 per million cached input tokens and $0.50 per million output tokens; its developer page lists a higher tier of $0.30/$0.012/$1.50 once context exceeds 200K.

Meta says Ember matches Claude Haiku 5.5’s best Artificial Analysis composite score at roughly one third of the cost and beats all GPT-6 Luna reasoning settings. Those comparisons use Meta-selected settings and partner tests, so the useful conclusion is narrower: Ember is a credible new candidate for cheap execution layers, but a routing policy should still be tested on one’s own tool schemas, error-recovery paths and long-context distribution. Meta reports that Ember remained below its high-risk thresholds and was tested for hidden-instruction resistance and human confirmation before high-impact actions. It is available through Meta Model API as `muse-ember-1.0`; Google also lists it in preview on its partner-model endpoint. [Meta research announcement](https://research.meta.ai/blog/muse-ember) · [Model and pricing page](https://dev.meta.ai/models/muse-ember) · [Google preview documentation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/meta/muse-ember-1-0)

### Known-exploited AI infrastructure: GPUStack and a narrow OpenSSH configuration

GPUStack is an open-source control plane for serving models and provisioning GPU workers. Its advisory says versions before 2.2.0 trusted loopback traffic as the built-in administrator by default. A same-host reverse proxy—or a forged `X-GPUStack-Real-IP: 127.0.0.1` header—could therefore turn a remote unauthenticated request into full administrative access. The resulting permissions include reading worker and cloud-provider secrets, creating permanent admin keys and reaching an inference-backend endpoint that can execute code on workers. The advisory says exploitation was observed against a 2.1.1 deployment. Version 2.2.0 removes the implicit loopback administrator path. [GPUStack advisory](https://github.com/gpustack/gpustack/security/advisories/GHSA-gj9m-f8ph-pmhr) · [CISA catalog search](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-102895)

OpenSSH CVE-2026-123158 is broad in brand name but narrow in configuration. It affects `sshd` before portable OpenSSH 10.6p2 on Linux when OpenSSH is built with musl libc and PAM is disabled; some affected account configurations accept an abnormally long password. Alpine-style deployments are the obvious review target, while Red Hat says its glibc-and-PAM builds are not affected. OpenSSH 10.6p2 contains the workaround. [OpenSSH 10.6p2 release notes](https://www.openssh.org/releasenotes.html#10.6p2) · [Red Hat scope note](https://access.redhat.com/security/cve/cve-2026-123158) · [CISA catalog search](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-123158)

### Google makes Pathways generally available on Google Cloud

Pathways is Google’s execution system for coordinating one model across multiple groups of accelerators. Instead of every worker running one lockstep program, a single Python client describes a distributed dataflow graph over virtual devices; the runtime places work, moves and reshards tensors, orders collectives and remaps work when a host fails. That is especially useful for heterogeneous reinforcement-learning pipelines whose sampler, reward model and trainer need different device groups and should overlap rather than wait on one another.

The November 9 announcement moves Pathways on Google Cloud to general availability. This is not a general replacement for Ray: Ray schedules Python tasks and actors across a cluster, while Pathways operates below that layer to coordinate JAX programs on TPUs. It is most relevant to organizations already training large models on Google Cloud, not ordinary application teams. [Google announcement and technical explanation](https://developers.googleblog.com/what-is-pathways-single-controller-training-for-large-models/)

## Open Source & Developer Tools

### Action radar · Claude Code 2.1.321 closes several agent-boundary failures

Claude Code 2.1.321 is a stable November 9 release. It fixes three distinct permission-boundary problems: MCP OAuth secrets could follow a redirect to another host; a command classified as read-only could run outside the sandbox without approval; and file protections could be missed when `cp` or `mv` wrote into a directory. It also fixes permission checks that evaluated a write from the wrong working directory and several data-loss risks when editing notebooks or files on network-mounted paths.

**Why it is worth acting on:** these are not cosmetic fixes. They affect whether credentials stay on the intended host and whether the agent asks before a write or an unsandboxed command. If Claude Code is part of a sensitive workflow, review this release before the next manual update. After updating, test one denied copy into a protected directory, one read-only shell command and one MCP OAuth redirect in a disposable repository. The release notes establish the fixes; they are not an independent audit of the sandbox. [Official release](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)

### Action radar · Qwen Code 0.27.1 makes background execution and LSP explicit controls

Qwen Code 0.27.1 is a stable November 9 release. It makes the default behavior of background agent execution configurable and adds a user-scoped setting and environment variable for Language Server Protocol integration. The larger release also lays the disabled-by-default foundation for watching pull-request state, exposes more session diagnostics, and adds optional personal memory backed by Mem0.

**Why it is worth testing:** the first two changes let a developer decide when agents keep work running and when repository language tooling is available, rather than accepting one global default. If Qwen Code is already in use, try the release in a disposable repository with background execution disabled first, then enable LSP deliberately and inspect which server starts. Treat PR watching and personal memory as separate trust decisions: both increase retained state or repository access, and the release notes do not provide an independent privacy or isolation audit. [Official release](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.1)

### Released November 9 · DBDelve 0.7.1 makes ODBC result grids editable

[DBDelve](https://github.com/ShayanAbbas1/dbdelve) is a native Rust/GPUI database client for macOS, Linux and Windows. It already supports common SQL databases, MongoDB, Redis-family stores and ClickHouse; an ODBC bridge reaches additional systems. Version 0.7.1 allows rows read through an ODBC plugin to be edited for PostgreSQL and generic SQL dialects.

The interesting part is the safety gate. DBDelve enables editing only when it can identify one schema-qualified table, a complete primary key, exact value round-tripping and driver-reported base-column metadata. It wraps generated writes in a transaction and rolls back unless every statement affects exactly one row; uncertain grids remain read-only and explain why. The app is still early, its benchmarks are project-authored, and the macOS build is not notarized. [Feature commit](https://github.com/ShayanAbbas1/dbdelve/commit/56fcba3883d02e59397ce2190feeaa53fa3df7ef) · [README and install limits](https://github.com/ShayanAbbas1/dbdelve)

### Recently popular / worth researching · RuView turns Wi-Fi CSI into experimental room sensing

[RuView](https://github.com/ruvnet/RuView) appeared in the pinned November 10 daily Trending snapshot. It combines a Rust sensing server, visualization, smart-home integrations and an MCP/CLI toolkit around Wi-Fi channel-state information (CSI). The project aims to infer presence, motion, breathing and heart-rate signals without cameras; its tooling labels output as measured, device-reported or synthetic instead of presenting every demo as a live measurement.

The fastest evaluation path is its Docker simulation, but that proves the software pipeline rather than the sensing claim. Real CSI needs supported hardware—typically three to six ESP32-S3 boards or a compatible Linux Wi-Fi adapter—and the project’s own guide says live 17-keypoint pose remains below target and is not a validated capability. This is best approached as a hardware-and-signal-processing research project, not a drop-in security or health monitor. [User guide](https://github.com/ruvnet/RuView/blob/main/docs/user-guide.md) · [Repository](https://github.com/ruvnet/RuView)

### Recently popular / worth researching · GBrain offers provenance-aware memory across agents

[GBrain](https://github.com/garrytan/gbrain) also appeared in the daily Trending snapshot and remained actively updated on November 9. It stores explicit facts with sources, supports corrections and withdrawal, exposes the same memory over MCP to multiple agent clients, and can be self-hosted under the MIT license. The useful distinction is that it can start without model keys using keyword retrieval; embeddings, synthesis, extraction and background enrichment are optional layers rather than prerequisites for every write.

Its memory boundary deserves more attention than the headline. Automatic session capture is opt-in, `forget` removes a fact from active recall but not all source material or backups, and configured cloud embedding or synthesis providers may receive stored text. Remote source grants do not automatically isolate callers that share local files or database credentials. A cautious first test is a disposable brain containing non-sensitive project facts, followed by explicit recall, correction and purge tests before any personal archive is connected. [README](https://github.com/garrytan/gbrain) · [Memory-boundary guide](https://github.com/garrytan/gbrain/blob/master/docs/guides/memory-boundaries.md)

### Recently popular / worth researching · HA-MCP gives agents a Home Assistant maintenance surface

[HA-MCP](https://github.com/homeassistant-ai/ha-mcp) is a standalone MCP server and Home Assistant integration with tools for device control, automation and dashboard editing, traces, logs, helpers, registries and backups. Unlike Home Assistant’s built-in MCP server—which is intentionally scoped to exposed Assist entities and intents—HA-MCP is designed to build, debug and maintain the installation. The recommended current path is the in-process integration through HACS or the Home Assistant 2026.11 Marketplace.

That power creates a larger trust boundary. Setup uses an administrator account or token; the project recommends a dedicated local-only admin rather than the owner’s login. Remote secret URLs are credentials, and beta file/YAML tools are off by default for good reason. The current branch is preparing a later stable release around Python 3.14 and real Home Assistant Core tests, so PyPI/`uvx` users should read the next release’s Python requirement rather than assuming today’s environment will upgrade in place. [README and setup](https://github.com/homeassistant-ai/ha-mcp) · [Python 3.14 compatibility work](https://github.com/homeassistant-ai/ha-mcp/commit/97fdc18eac0eb71819b6eff87d56ad3a2a540165)

### Upstream watch · Codex improves OAuth model catalogs and deferred MCP visibility

Two November 9 commits address small but consequential control-plane gaps. Aggregate MCP resource listings now include a sorted `deferredServers` field, so callers can discover dormant servers by name and query them explicitly instead of treating them as absent. Custom gateway providers can also refresh a model catalog with existing OAuth credentials when the catalog URL and base URL share an origin, without requiring a separate API key or interactive login. A third commit allows the terminal status to return to Done while explicitly backgrounded processes keep running.

These are upstream commits, not a stable-release promise. They matter because they make lazy MCP and enterprise gateway setups more observable, but users should wait for the relevant release or build from a known commit rather than assuming an installed Codex already has them. [Deferred MCP servers](https://github.com/openai/codex/commit/27fcd7cbedd7efd63fd704bd01a0cfe1d7b85a26) · [Gateway OAuth model catalog](https://github.com/openai/codex/commit/6222faa3c463442b3788b2690108568786f6ffc7) · [Background-terminal status](https://github.com/openai/codex/commit/4f9e7171a1f3334ab22123aba61daa5af37f289e)

## Business Opportunities

### Exposure checks for self-hosted AI control planes

**Observed need:** GPUStack and Redpanda Connect show the same operational failure pattern—an administrative or code-executing API becomes reachable through a reverse proxy or default bind without the authentication boundary operators assume. **Why now:** small teams increasingly self-host inference and data pipelines but rarely have dedicated platform-security staff. A narrow product could inventory listening ports, proxy headers, product versions and authentication modes, then produce a read-only evidence report with exact vendor references. A low-cost validation is to interview five GPUStack, Redpanda or Home Assistant operators and run a local-only scanner against intentionally vulnerable containers. The risk is false reassurance: configuration checks cannot prove that every network path or credential is safe. Sources: [GPUStack advisory, July 31; exploited-in-the-wild detail current November 9](https://github.com/gpustack/gpustack/security/advisories/GHSA-gj9m-f8ph-pmhr) · [Redpanda advisory, November 9](https://github.com/advisories/GHSA-h882-2qpw-598h)

### Trust gates for API-spec-to-code workflows

**Observed need:** teams often treat OpenAPI files as documentation, while generators execute the resulting Python during CI imports and application startup. The three FastAPI generator advisories show that a hostile spec is closer to source code than to inert JSON. A small product could lint incoming specs for code-generation sinks, run generators in a disposable sandbox and diff the generated AST before allowing it into a build. The cheapest validation is an open-source pre-commit rule covering the three published payload classes, followed by outreach to internal-platform teams that accept partner specs. The risk is a narrow market and fast upstream remediation; the durable value would need to cover multiple generators and languages, not one abandoned package. Sources: [GHSA-p2mm-64f6-gmpp](https://github.com/advisories/GHSA-p2mm-64f6-gmpp) · [GHSA-6xmv-cjr5-w3q8](https://github.com/advisories/GHSA-6xmv-cjr5-w3q8) · [GHSA-h667-4jj2-cgv4](https://github.com/advisories/GHSA-h667-4jj2-cgv4)
