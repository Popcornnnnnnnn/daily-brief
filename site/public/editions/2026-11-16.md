## Tech & AI

### Catch-up — Notion AI transcripts were included in the Fireworks incident

Notion’s advisory was originally published on **November 12** and received visible updates on **November 11 and 13**. It says the Fireworks dataset included Notion AI chat transcripts used by the Insights feature. For the vast majority of affected workspaces, the transcripts were unattributable and did not include tool-call results. Notion disabled Insights, stopped serving open-weight models through Fireworks, revoked exposed Notion API keys found in affected messages on November 11, and reported exposed third-party API keys to their issuers on November 12.

The practical boundary matters: Notion says it has contacted identified affected customers. If you have not heard from Notion, it has not identified your workspace as affected and says no action is needed at this time. A contacted customer should treat the supplied impacted data as exposed and rotate any passwords, API keys or other credentials pasted into the affected Notion AI chats. This is **not** evidence that every Notion workspace or every Notion page was exposed.

Fireworks’ own November 9 update attributes the broader incident to a financially motivated LLM-jacking group. It says some account and billing information was affected and, for a limited set of accounts, secrets, datasets and incomplete models were also accessed. Fireworks says inference, the Training SDK and Nexus were not found affected and are zero-data-retention by default; its investigation remains ongoing.

[Notion security advisory](https://www.notion.com/security/advisories/security-incident-involving-a-third-party-ai-vendor) · [Fireworks incident update](https://fireworks.ai/security/bulletins/october-2026-security-incident-update)

### Effective today — GitHub Copilot model retirements

GitHub’s October 15 notice takes effect on **November 16** across Copilot Chat, inline edits, ask and agent modes, and code completions:

- Claude Opus 4.8 → Claude Opus 5.5, except annual individual subscribers retain 4.8

- Claude Opus 5 → Claude Opus 5.5

- GPT-5.6 Terra → GPT-6.1 Sol or GPT-6 Luna

If an integration, policy or benchmark pins one of the retired models, change it rather than relying on automatic selection. Enterprise and Business alternatives are automatically enabled only when administrators have not disabled the relevant global or model policy.

[GitHub Changelog](https://github.blog/changelog/2026-10-15-upcoming-deprecation-of-selected-github-copilot-models-in-mid-November/)

### Catch-up — Antigravity /teamwork exposes a useful multi-agent design pattern

**Actual announcement date: November 13.** Google Research made Antigravity’s `/teamwork` available to external researchers and developers. The reusable idea is more important than the product name: parallel agents explore different candidates, objective falsifiers such as unmodified test suites or proof checkers reject weak results, and fresh-context critics audit work without inheriting the producer’s reasoning. Coordinators also partition files and tools so a long-running job does not accumulate one overloaded context.

Google reports results across formal proofs, systems work and kernel optimization, but these are Google-led case studies rather than an independent general-purpose benchmark. Some specialized workflows are still promised for later. This is worth studying for long, parallelizable tasks with a hard verifier; it is not evidence that adding more agents improves ordinary sequential coding work.

[Google Research announcement](https://research.google/blog/advancing-science-engineering-with-antigravitys-teamwork-feature/)

## Open Source & Developer Tools

### Recent update — NVIDIA SkillEvaluator makes Agent Skills testable

**Actual update date: November 15.** NVIDIA’s repository moved its NVIDIA Build default to Nemotron 3.5 Lightning after the previous hosted endpoint returned HTTP 404, and moved the Anthropic and Bedrock SkillSpector defaults to Claude Opus 5.5 after verifying structured output. The larger project is more useful than the model-name change: Tier 1 provides deterministic quality and security gates, Tier 2 checks semantic overlap, and Tier 3 compares agent performance with and without a skill in a sandbox.

This is a concrete answer to a common weakness in skill marketplaces: a polished [SKILL.md](http://skill.md/) is not proof that the skill helps. Tier 1 can run without an API key; live evaluation needs model credentials, sandbox setup and potentially paid inference. NVIDIA also warns that readiness checks do not prove inference success and that generated evaluation cases need human review.

### Release — Turbo Browser MCP 0.5.0 adds proof, idempotency and human handoff

**Actual update date: November 15, 22:05 Shanghai time.** The v0.5.0 commit adds three safeguards for agent-driven form submission:

- `expect` waits for evidence such as a URL, selector or receipt text and reports whether submission was verified.

- `submissionKey` writes an idempotency ledger and refuses a duplicate submit unless explicitly allowed.

- Modal and optional network guards catch commits that do not look like ordinary “Submit” buttons, including several Chinese, Japanese, Korean and Vietnamese labels.

It also adds `wait_for_human` so an agent can hand a step to a person and resume in the same session. The project’s token and speed numbers are author-run local benchmarks, not independent validation. It is still a young Playwright-based MCP server; test it against a disposable account before trusting it on payments or irreversible portals.

[Official repository and v0.5.0 documentation](https://github.com/Tthanh2k6/turbo-browser-mcp) · [v0.5.0 commit](https://github.com/Tthanh2k6/turbo-browser-mcp/commit/8fd436e78cc0e191be1aa69c69a3daa643a6a5e1) · [Show HN discussion](https://news.ycombinator.com/item?id=50507033)

### Recent discovery — db-branch gives agents disposable MySQL and PostgreSQL branches

**Actual public activity date: November 15.** db-branch appeared on Show HN during this report window. It creates copy-on-write MySQL or PostgreSQL branches on ZFS, then exposes them through a CLI, REST API, web console and MCP server. The intended workflows are risky migrations, per-PR databases and isolated agent experiments; reset, checkpoints and TTL cleanup make destructive testing recoverable.

The trade-off is substantial infrastructure: it is beta, APIs may change, and installation requires Ubuntu 24.04 or 26.04 plus ZFS. The project reports roughly 0.5-second PostgreSQL and 3-second MySQL branches on its own three-node test cluster; those are author measurements, not independent benchmarks.

### Recent hot project — Tencent LoopForge turns agent runs into approval-gated SOPs

**Trending snapshot date: November 15.** LoopForge ranked 7 in the daily snapshot with 484 stars gained. It is a self-hosted workflow layer for Codex, Claude Code and CodeBuddy: isolated workspaces, reusable SOP graphs, artifact dependencies and human approval gates sit around the underlying coding agent. This is most interesting for teams that need repeatable delivery and review rather than another chat surface.

The limitation is operational: self-hosting the control plane does not make arbitrary agent code safe by itself. You still need container isolation, credential boundaries, repository permissions and review rules. The project is active, but its fast-moving surface and large integration scope deserve a sandboxed evaluation.

### Catch-up release — browser-use 1.0.5 adds an automatic run judge

**Actual release time: November 14, 16:24 Shanghai time.** The release adds one low-effort model request after each browser run and writes a structured `result.judgement`: success, failure reason, description, prompt-injection detection, bot or CAPTCHA detection, and site-specific gotchas. Custom `judge_context` can supply acceptance criteria, and `judge=False` disables the extra call.

This is useful for regression tests and unattended browser tasks because it turns a vague final answer into an explicit verdict and preserves failures such as rejected input formats. It is still self-evaluation by the configured model, not an independent security boundary. The project’s 13-run comparison is author-reported, and the judge adds latency and inference cost. Try it first on a replayable task with a known expected result, then compare the verdict against a deterministic assertion.

[Official browser-use 1.0.5 release](https://github.com/browser-use/browser-use/releases/tag/1.0.5)

## Business Opportunities

### A lightweight Skill CI service for small teams

**Evidence:** SkillEvaluator now offers reproducible static and live skill checks, while multiple skill collections are drawing current developer attention. **Hypothesis:** teams adopting skills will pay for a simple pull-request gate that runs deterministic checks, records versioned evidence and optionally schedules a controlled before/after agent evaluation.

A low-cost test is to wrap Tier 1 around 10 public skills, publish a compact pass/fail card and ask five teams whether they would pay for hosted CI and review history. The main risk is that GitHub Actions templates and SkillEvaluator itself may make a thin wrapper too easy to copy; value would need to come from policy, evidence retention and safe sandbox operations.

### A guarded submission layer for browser agents

**Evidence:** Turbo Browser MCP’s Show HN feedback produced explicit submission proof, idempotency and network guards. **Hypothesis:** teams automating admin portals need an independent “transaction firewall” between an agent and irreversible actions.

A small validation is to support one narrow workflow—expense claims or vendor onboarding—with preview, approval, idempotency keys and a signed action receipt. Risks include site-specific behavior, liability for missed guards and the need to avoid becoming a credential-handling proxy.
