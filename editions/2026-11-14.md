## Today in 90 seconds

- **OpenAI moved agentic commerce from product discovery to payment.** ChatGPT Wallet lets an eligible US Pro user add a card once, review the items, total and card, then approve each purchase with a biometric check. The merchant and agent receive a network payment token rather than the actual card details. It starts in dots, not ordinary ChatGPT, Work or standalone Codex threads, and it is still a limited US rollout.

- **llama.cpp 1.0 is a real platform release, not just a version badge.** It removes deprecated public APIs, adds FP8 KV caches and a host-memory MoE expert cache, expands model, vision and TTS support, hardens the server against SSRF, CORS and DNS-rebinding paths, and redesigns the web UI. Downstream applications need to budget for breaking API work.

- **Codex CLI 0.169.0 makes parallel terminal work more durable.** It adds persistent side-chat tabs, task search, collapsible completed turns and, when custom gateway onboarding is enabled, terminal-based provider setup. It also keeps project configuration and MCP servers disabled in untrusted directories until the user explicitly opts in with `--trust`.

- **Operational risk showed up in both cloud services and telemetry.** Microsoft's public status page reported degradation across Microsoft 365 and consumer services, while a newly indexed OpenTelemetry JavaScript advisory shows that inbound signed-URL credentials could be exported in plaintext to tracing backends before version 0.222.0.

## Tech & AI

### ChatGPT Wallet gives agents a user-approved payment credential

OpenAI launched **ChatGPT Wallet** on November 13. A user adds an eligible card once; before each purchase, they review the items, total and selected card, then approve with Face ID, a fingerprint or another supported security check. The payment network issues a substitute card credential with its own number, security code and expiration date. The actual card details are not shared with the merchant or the agent, and eligible card rewards and dispute protections remain in place.

The launch matters because it closes the loop from agent-assisted discovery to checkout without requiring merchants to adopt a new payment rail. OpenAI is also publishing a Commerce Partner Playbook covering product feeds, Web Bot Auth, agent access through CDNs and firewalls, payment-risk systems, plugins and WebMCP tools. The company says it is working with American Express, Mastercard, Visa, several fraud-prevention vendors and payment processors.

The limits are material. Wallet starts in **dots** for US ChatGPT Pro subscribers aged 18 or older with eligible US-issued cards and a US billing address. OpenAI's help page says it is not available in ordinary Chat, Work or standalone Codex threads. The initial model requires approval for each transaction; parameter-based pre-approval is a future direction, not a current capability. Merchant compatibility is also uneven: agent traffic can still be blocked and risk systems may decline legitimate tokenized purchases.

[OpenAI announcement, November 13](https://openai.com/index/introducing-chatgpt-wallet/) · [Wallet help and eligibility](https://help.openai.com/en/articles/20001654-making-purchases-with-chatgpt-wallet) · [Commerce Partner Playbook](https://developers.openai.com/commerce/)

### Security brief — OpenTelemetry JavaScript could export signed URL secrets to traces

*Original repository advisory: November 9. Added to the GitHub Advisory Database and reviewed on November 13; included now as a catch-up with the actual dates stated.*

The HTTP instrumentation package redacted sensitive query parameters on outgoing spans but not on incoming server spans. A service receiving an S3 presigned URL, Azure SAS token, GCS signed URL or signature-authenticated webhook could therefore write the live credential into the `url.query` trace attribute. Anyone with trace-read access—or the observability provider itself—could see it. The existing `redactedQueryParams` option did not protect this inbound path.

The affected range is `@opentelemetry/instrumentation-http &gt;=0.204.0, &lt;0.222.0`. Version **0.222.0** redacts known sensitive parameters on incoming spans by default and adds `redactedQueryParamsServer` for customization. GitHub rates the issue Moderate because useful exploitation requires both a credential-bearing inbound URL and access to the tracing backend. That scope should not be minimized: observability access is often much broader than access to the original credential.

[GitHub Advisory GHSA-3v2p-hm54-8qcq](https://github.com/advisories/GHSA-3v2p-hm54-8qcq) · [OpenTelemetry JS 0.222.0](https://github.com/open-telemetry/opentelemetry-js/releases/tag/experimental/v0.222.0)

### Security catch-up — Nuxt page-route controls could be bypassed with a leading double slash

*Original Nuxt advisory: November 2. The GitHub Advisory Database entry was refreshed in this report window; included because the event was absent from the recent briefs.*

Nuxt 4.6.0 through 4.6.3 could resolve a request such as `//x/admin` to the `/admin` page while Nitro route rules and `server/middleware` continued to see the unmatched double-slash path. That mismatch could skip a route-scoped authentication handler, redirect or security header. API handlers under `server/api` and `server/routes`, page middleware declared with `definePageMeta`, Nuxt 3.x and Nuxt 4.0–4.5 were not affected.

The fix is `@nuxt/nitro-server@4.6.4`, pulled in by Nuxt 4.6.4. The project's workaround is to reject request paths beginning with `//` in server middleware or normalize repeated slashes at the reverse proxy. This is a path-consistency bug, so teams should test authorization at the exact layer that ultimately selects the page.

[Nuxt advisory GHSA-r99w-jh2x-3mg9](https://github.com/nuxt/nuxt/security/advisories/GHSA-r99w-jh2x-3mg9)

## Open source & developer tools

### Action radar — Codex CLI 0.169.0 makes parallel work easier to resume

OpenAI released **Codex CLI 0.169.0** on November 13. The opt-in terminal workspace now supports multiple side-chat tabs that can be reopened after a restart, while the agent command center can search older tasks by name, prompt preview or working directory. Completed tool activity can be collapsed without hiding answers or removing it from search.

With custom gateway onboarding enabled, the release also adds terminal-based creation and editing of custom model providers, including device-code authorization for supported gateways over SSH or without a local browser. On macOS and Linux, an opt-in Cloud connection can send images, select a model and reasoning effort, and archive or restore Cloud conversations from the terminal.

**This is worth a focused trial if you already use Codex for parallel investigations or switch between local and gateway-backed work.** The safest first check is a non-sensitive repository: confirm that side chats survive a restart, older tasks remain discoverable, and project configuration plus MCP servers stay disabled in an untrusted directory. The last behavior is an explicit security fix; `codex exec` and `codex review` now require `--trust` before saving project trust.

[Codex CLI 0.169.0 release](https://github.com/openai/codex/releases/tag/rust-v0.169.0)

### llama.cpp 1.0 establishes a cleaner local-AI foundation

llama.cpp released **v1.0.0** on November 13. The version removes 35 deprecated functions and other legacy public interfaces, promotes the speculative NextN API into `llama.h`, and ships matching ggml 1.0 changes. That cleanup is useful for maintainers, but it is intentionally breaking for downstream applications that embed the library.

The capability changes are substantial: FP8 KV caches; a host-memory MoE expert cache with configurable CPU share; external PLE/engram shards; new text, vision and TTS architectures; an OpenAI-compatible `/v1/audio/speech` endpoint; and Gemma 4 streaming audio input. The server also adds explicit opt-ins for unauthenticated tools and private media URLs, fixes CORS, DNS-rebinding and SSRF paths, restricts `HF_TOKEN` to Hugging Face hosts, and cancels MCP tool calls when a client disconnects or times out.

The redesigned web interface adds grouped chats, a live-preview Markdown editor, better mobile layouts, PDF thumbnails and chat search. The practical upgrade path is therefore two-part: review API removals in embedded integrations, then retest server security policy and UI workflows rather than assuming a drop-in replacement.

### Recent popular — Alibaba OpenCodeReview pairs deterministic coverage with an LLM agent

*Current signal: GitHub Trending daily snapshot on November 14 at the report cutoff; v1.13.9 released November 13. Included because the repository and current event were absent from the recent briefs.*

[OpenCodeReview](https://github.com/alibaba/open-code-review) is a code-review CLI that hard-codes file selection, bundling, rule matching and comment positioning, while giving an LLM agent the dynamic work of retrieving context and reasoning about defects. It can review worktree changes, branch ranges or commits, scan whole files, run in CI, and delegate the reasoning step to an existing coding agent without a separate model key.

Alibaba says the approach came from an internal service used by tens of thousands of developers and reports higher precision and F1 than a general-purpose agent on its AACR-Bench, with lower token use but lower recall. Those are project-authored benchmark claims; the 50-repository, 200-PR dataset is public, but a team should reproduce the result on its own code and defect mix.

Version 1.13.9 records excluded files in run coverage, surfaces warnings even when a PR has no findings, enforces per-request tool declarations and updates vulnerable compatible dependencies. A low-risk first evaluation is to save JSON output from a small PR and manually score precision, missed issues and excluded-file coverage.

### Recent popular — Plannotator makes asynchronous agent review a local workspace

*Current signal: GitHub Trending daily snapshot on November 14 at the report cutoff; v0.28.64 released November 13. Included because it had not appeared in the recent briefs.*

[Plannotator](https://github.com/backnotprop/plannotator) opens plans, diffs, rendered HTML, agent questions and artifacts in a local browser review surface. A user can annotate the material and send feedback back to Claude Code, Codex, Copilot CLI, Gemini CLI, OpenCode, Pi and other supported agents. Its Inbox is designed so the agent does not need to keep a session blocked while a person reviews the work.

Version 0.28.64 is a small but practical release: compressed installers reduce the Apple-silicon download from 195.6 MB to 44.9 MB with `.tar.xz`; the Artifacts page gains a Videos filter; GitLab whole-file comments become separate threads; and PR images and videos can appear in the Inbox when code-review capability is enabled. The project says plans, diffs and annotations stay local by default, but release checks, remote-review retrieval, AI features, URL fetching and hosted Workspaces have their own network boundaries. Review those before using it on sensitive code.

### Recent popular — Tailcat turns the Tailscale data plane into a peer-to-peer netcat

*Current signal: GitHub Trending daily snapshot on November 14 at the report cutoff; original open-source release was August 2026. Included as a newly discovered project, not a same-window release.*

[Tailcat](https://github.com/tailscale/tailcat) creates end-to-end encrypted WireGuard tunnels between two machines using Tailscale's data-plane pieces and DERP for bootstrap and relay, without the Tailscale control plane or a Tailscale account. One side receives a short address and shares it out of band; the other connects with the CLI. It does not need root access or alter routing tables or DNS.

Beyond piping stdin and stdout, it can forward local ports, expose an exit node, serve SSH with explicit authorized keys, copy files and run a command per connection. An experimental WebAssembly demo can exchange text or files with the CLI, although browser traffic is DERP-relayed until WebRTC support exists.

The limits are explicit: no API, CLI or wire-format stability promise; free relay service is rate-limited with no uptime or throughput SLA; and an address can function as a credential. The `no-auth-ssh` mode should never be published. This is worth studying as a small, composable secure transport, not as a managed-network substitute.

[Tailcat repository](https://github.com/tailscale/tailcat) · [Experimental browser demo](https://tailscale.github.io/tailcat/) · [Threat model](https://github.com/tailscale/tailcat/blob/main/SECURITY.md)

### Worth researching — Block Buzz treats people, agents and workflows as signed events

*Current signal: GitHub Trending daily snapshot on November 14 at the report cutoff. The current repository describes an active 0.x line; included as a discovery rather than a new release.*

[Buzz](https://github.com/block/buzz) is a self-hostable workspace built around a Nostr relay. Messages, reactions, workflow steps, approvals and Git events share one signed event log, and agents receive their own identities, channel memberships and audit trail. The repository currently ships channels, threads, DMs, canvases, search, desktop clients, YAML-triggered workflows, a Git-event layer and an agent-oriented JSON CLI.

The architectural idea is interesting: a branch can become a room where patches, CI, review and approval live together, and an agent can search the history with receipts. The project is also candid about unfinished areas—mobile clients, workflow approval glue and several federation ideas. It has heavy local prerequisites (Docker plus Hermit or a recent Rust/Node/pnpm stack), and its plugin API is still a preview. Evaluate the event model and audit properties before considering the workspace surface.

[Buzz repository and architecture](https://github.com/block/buzz)

## Business opportunities

### Agent-commerce readiness checks for small merchants

**Observed signal:** OpenAI now gives eligible users an agent payment credential, while its own launch notes warn that CDNs, bot controls and payment-risk systems can block legitimate agent transactions.

**Hypothesis:** A small team could offer a fixed-price readiness check that verifies structured product data, signed agent requests, checkout compatibility and false declines without replacing the merchant's existing payment stack. Validate cheaply by testing five consenting US merchants against the public Commerce Partner Playbook and documenting where an agent is blocked or a tokenized purchase is misclassified. Risks include limited geographic availability, platform-policy changes, payment compliance, fraud liability and dependence on one distribution channel.
