## Tech & AI

### OpenAI hardens GPT-6.2 against adversarial distillation

OpenAI published a security note on **November 20** describing defenses against unauthorized extraction of model capabilities—especially exact internal reasoning traces. Its stack combines adversarial training, input and output classifiers, API controls that bind protected reasoning to the conversation history, and campaign-level detection and enforcement. Tool-call arguments are included in leak checks because protected material can escape through tool inputs even when the final answer is clean.

In OpenAI’s internal adaptive evaluation, average attack success reportedly fell from **54.0% for GPT-6 Astra with its original safeguards to 0.2% for GPT-6.2 Astra with updated safeguards**. This is not an independent audit, and the two endpoints combine a newer model with newer safeguards. Still, the engineering lesson is concrete: model providers increasingly need cross-layer abuse controls, not a single refusal layer.

[OpenAI: Combatting adversarial distillation](https://openai.com/index/combatting-adversarial-distillation/)

### Major unverified claim: a Claude-assisted Riemann Hypothesis proof

Mathematician Levent Alpöge says he and Claude found proofs of the Riemann Hypothesis and the Generalized Riemann Hypothesis and formalized them in Lean without assumptions. He released an announcement and links to fourteen archive parts, but not yet a readable proof exposition.

**This should not be read as “the Riemann Hypothesis has been solved.”** State of Proof records the claim as an intake only and says examination has not started. The first useful check is bounded and technical: locate the exact Lean declarations, compare their definitions and quantifiers with the standard RH and GRH statements, pin the dependency tree, and replay the relevant declarations in isolation. Until that happens—and experts can understand the mathematical argument—the result remains an extraordinary claim under review.

> **Media (PDF):** [Levent Alpöge’s November 20 announcement. It is the claimant’s own account, not independent validation.](https://alpo.ge/remark.pdf)

[Independent intake and check plan — State of Proof](https://stateofproof.org/paper-watch/paper-2026-11-20-a-claimed-proof-of-the-riemann-hypothesis)

### MedChemBench tests whether models can reason across molecular trade-offs

OpenAI introduced **MedChemBench** on November 20: 99 problems drawn from 117 papers and patents, covering 761 molecular structures. It scores structure reconstruction, evidence-grounded scientific reasoning, compound ranking and selection, and numerical property prediction.

![MedChemBench overview: molecular structures, scientific explanation, ranking and property prediction. Source: OpenAI, November 20, 2026.](https://images.ctfassets.net/kftzwdyauwt9/6kbw4PSOhEqlbbiM3ZYhOb/1c770a466f57e0117f970cb124b921ee/introducing-medchembench-header-poster-4k.png?fm=webp&q=50&w=3840)

OpenAI reports GPT-6.2 Astra at **84.5% of available credit** at xhigh. More informative than the headline score is the uneven profile: structure reconstruction was strong, while selecting compounds and predicting numerical properties remained much harder.

![A MedChemBench PRMT5 example shows why optimizing one medicinal-chemistry property can worsen another. Source: OpenAI.](https://images.ctfassets.net/kftzwdyauwt9/6EY1OYOVnL6SZTDp6zttc8/e2c458548218cb5cd764b05f627f573c/introducing-medchembench-prmt5-poster-4k.png?fm=webp&q=50&w=3840)

The limitation matters: these are retrospective tasks from published sources, prior training exposure cannot be ruled out, and models had no tools, experimental feedback or new laboratory results. The benchmark does **not** show that a model can discover new drugs or improve real lab decisions.

[OpenAI: Introducing MedChemBench](https://openai.com/index/introducing-medchembench/) · [Paper](https://cdn.openai.com/pdf/medchembench.pdf)

### Security quick brief: four newly catalogued exploited vulnerabilities

CISA’s November 20 KEV feed added four entries with a November 23 remediation date for covered federal systems:

- [CVE-2026-123890](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-123890) — VMware vCenter authentication bypass.

- [CVE-2025-42884](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2025-42884) — SAP NetWeaver Enterprise Portal JNDI-related injection.

- [CVE-2026-129448](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-129448) — Apache Roller unauthenticated XML-RPC deserialization leading to code execution.

- [CVE-2026-76466](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search_api_fulltext=CVE-2026-76466) — Cisco Expressway hard-coded credentials affecting clustered devices.

The action is environment-dependent: first establish whether any affected product/version is present and exposed, then follow the vendor mitigation. KEV inclusion is evidence of observed exploitation, not proof that every installation is compromised.

## Open source & developer tools

### Action radar — Codex CLI 0.171.0 makes the TUI a fuller agent workspace

Codex CLI is OpenAI’s terminal coding agent. Version 0.171.0 turns on the TUI workspace by default, adding searchable document and image previews plus subagent transcripts beside the main conversation. It also adds `codex exec --remote <ADDR>` for starting or resuming noninteractive sessions on an existing app server, plus custom MCP status lines behind the `tui_extensions_statusline` flag.

**Why it is worth trying:** the workspace can reduce context switching when a task uses screenshots, documents or parallel agents. Test it on one disposable session and confirm that resume, permission profiles and approval behavior still match your workflow. This is a stable release, but the remote-control and status-line paths are new enough to treat as a bounded pilot.

[Official release notes](https://github.com/openai/codex/releases/tag/rust-v0.171.0)

### Action radar — Claude Code 2.1.329 fixes macOS sign-in and surfaces hidden automation

Claude Code is Anthropic’s terminal coding agent. Version 2.1.329 fixes repeated macOS sign-outs when Keychain reads succeeded but writes failed, and prevents `~/.claude.json` from being reset after a transient read failure. It also shows scheduled tasks, loop wakeups, goals and conversation forks in `/tasks`, and exposes remote MCP refusal messages in `/mcp`.

**Why it is worth trying:** macOS users who saw recurring authentication failures now have a concrete reason to retest. The expanded task view also makes background automation easier to audit. If you use hooks or managed marketplaces, review the new warnings rather than treating a clean start as proof that every policy loaded.

[Official release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.329)

### Action radar — Gemini CLI 0.70.0 tightens command policy and resume behavior

Gemini CLI is Google’s open-source terminal agent. Version 0.70.0 preserves the selected worktree across authentication restarts, skips system MCP servers whose commands have insecure permissions, and changes command-policy matching so `commandPrefix` and `commandRegex` apply to the top-level command argument. It also keeps shell commands with unresolved expansion behind an `ASK_USER` decision.

**Why it is worth trying:** these are meaningful safety and continuity changes for headless or multi-worktree use. Before relying on the release, run a small policy regression check against representative allowed, denied and variable-expanded commands; the matcher change may alter existing assumptions even though the release notes present it as a fix.

[Official release notes](https://github.com/google-gemini/gemini-cli/releases/tag/v0.70.0)

### Harness adapters: train the model inside the agent runtime it will actually use

Hugging Face trained separate LoRA adapters for **Qwen3.8-27B** inside pi, Hermes Agent and OpenCode, then merged them into a single “super-adapter.” The key design choice is to keep the production harness in the training loop instead of rebuilding a simplified agent loop inside the RL framework.

![The harness-adapter task pipeline filters generated and real-world coding tasks before RL training. Source: Hugging Face, November 20, 2026.](https://huggingface.co/buckets/huggingface/harness-adapters-blog-assets/resolve/images/task-pipeline.png)

Hugging Face reports that, with thinking off, the super-adapter raised mean pass@1 from **39.5% to 49.0%** across six harness/benchmark pairs. With thinking on, the reported mean moved from 55.5% to 63.5%. On tasks both models solved, it also used far fewer tool calls and tokens. Specialist adapters were often better when only one harness mattered.

![Blocked tool calls declined during training; this is an author-reported safety signal, not an independent guarantee. Source: Hugging Face.](https://huggingface.co/buckets/huggingface/harness-adapters-blog-assets/resolve/images/safeagents-blocked.png)

Important limits: there was one attempt per task, Terminal-Bench influenced a merge-weight choice and is therefore slightly optimistic, and the authors observed “thinking leakage” behavior that deserves follow-up. Still, this is a practical recipe with models, data and training details available.

[Full technical post](https://huggingface.co/blog/harness-adapters-at-scale) · [Super-adapter model card](https://huggingface.co/harness-hub/Qwen3.8-27B-super-adapter)

### Recent discovery — replit/amuse (first observed November 19)

**Why it is worth researching:** Amuse is a new Apache-2.0 self-hosted personal agent that combines sourced web research, a live browser with takeover, reminders and monitors, editable file-based memory, goal plans, small persistent apps, and approval cards for consequential actions.

![Amuse onboarding demo. Source: the project repository.](https://raw.githubusercontent.com/replit/amuse/main/docs/media/hatch.gif)

![Amuse live-browser demo. Source: the project repository.](https://raw.githubusercontent.com/replit/amuse/main/docs/media/browser.gif)

The boundary is explicit: it is designed for one person on one computer, has **no login**, listens on [localhost](http://localhost/), requires PostgreSQL and an OpenAI API key, and should not be exposed to a network. Docker is the isolation boundary for the bundled Chromium configuration. That makes it easy to explore, but not a ready-made multi-user or internet-facing service.

[Repository and quick start](https://github.com/replit/amuse)

## Business opportunities

### Harness-specific agent optimization as a small-team service

**Observed signal:** Hugging Face’s results suggest that training and evaluating a model inside the exact agent harness can improve both task completion and tool efficiency. **Business hypothesis:** teams with custom coding agents may pay for a bounded “harness performance audit” that measures failure modes, tool-call waste and candidate LoRA improvements without replacing their whole stack.

A low-cost validation is a paid design-partner pilot on one internal harness: define 20–40 representative tasks, establish a reproducible baseline, then test prompt/runtime changes before any fine-tuning. The main risks are benchmark overfitting, leaking proprietary code into training data, GPU cost and improvements that disappear after the harness changes.
