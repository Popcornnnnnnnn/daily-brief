## Tech & AI

### Follow-up — the Riemann proof is now formally verified

Yesterday's edition treated Levent Alpöge's Claude-assisted proof as a major but unverified claim. On November 21, the Lean and Mathlib communities issued a joint statement, endorsed by the Lean FRO and the Mathlib Initiative, saying they have full confidence in the proof.

The verification is unusually concrete:

1. The target theorem is Mathlib's vetted formal statement of the Riemann Hypothesis.

2. Dozens of people compiled the library and reproduced the same raw proof export.

3. Two comparison tools confirmed that Alpöge's theorem is exactly the Mathlib statement.

4. Lean's kernel, `con-leche`, `con-ron`, and independent checkers accepted an inert proof export, reducing the risk that executable source code could tamper with the check.

**What changed:** this is no longer merely an author claim with a repository attached. It is a community-certified formal proof artifact with independent checker diversity. **What remains:** formal validity does not automatically provide a short human explanation, establish which ideas are genuinely new, or complete ordinary mathematical exposition and peer review.

[Lean and Mathlib joint statement](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/) · [Extended verification overview](https://math.mit.edu/~drew/grh/) · [Original proof note](https://alpo.ge/remark.pdf)

### C++26 is complete again after the first ballot setback

The ISO C++ committee says it has completed technical work on C++26 for a second time. The first Draft International Standard ballot did not pass unanimously, largely because of late concerns about contracts. At the November meeting in Búzios, the committee revisited those comments, kept contracts in C++26, adopted an `enforced` label for preconditions, postconditions and assertions, and voted 111–9, with eight abstentions, to reship the standard.

Other C++26 changes improve reflection with modules, memory allocation control for senders/receivers, and structural types. Work on C++29 also continued, including `0o` octal literals, `std::ranges::any_view`, `views::slice` and `optional::get_ptr()`.

**Practical impact:** teams should still treat C++26 as pending its second approval ballot and final editorial publication, but compiler and library experiments can now target a more stable feature set.

[Herb Sutter's official committee trip report](https://herbsutter.com/2026/11/21/c26-is-done-again-trip-report-november-2026-iso-c-standards-meeting-buzios-brazil/)

### Catch-up — Microsoft To Do apps retire on June 30, 2027

**Actual announcement date: November 18.** Microsoft will retire the To Do apps on web, Windows, Mac, iOS and Android on June 30, 2027. For work and school accounts, Planner's redesigned My tasks experience begins rolling out in December 2026. Existing To Do tasks will remain visible in Planner until the retirement date, but Microsoft says they will not migrate into the new private Planner plan.

The most important limitation is for personal Microsoft accounts: Planner is not available there, so those users need to choose another task app. To Do service APIs and synchronization support have separate later retirement timelines; Microsoft has not yet supplied those dates.

[Microsoft announcement](https://techcommunity.microsoft.com/blog/PlannerBlog/introducing-unified-tasks-and-plans-for-copilot-and-microsoft-365/4573958) · [Migration guidance](https://support.microsoft.com/en-us/planner/to-do-to-planner)

### Security catch-up — PHP session files and OpenJDK Base64 decoding

**Actual bulletin date: November 20.** Google Cloud warned that CVE-2026-126714 can turn a partially written PHP session file into unauthenticated remote code execution when the default file-based session handler later deserializes attacker-controlled data. Fixed PHP versions include 8.5.13, 8.4.28, 8.3.37 and 8.2.36. End-of-life lines do not receive a patch. Google recommends disabling session upload progress when it is not needed and rebuilding or redeploying once patched managed images are available.

Google also updated its CVE-2026-114938 guidance: an integer underflow in HotSpot's AVX-512 VBMI Base64 decoder can cause an out-of-bounds write and potential remote code execution. Patched Java 17, 21 and 25 base images have finished rolling out to several serverless products, but custom containers, some jobs and worker pools still require a rebuild or the documented AVX mitigation. Applicability depends on JDK line, CPU capability and JVM flags; this is not a blanket claim that every Java workload is exploitable.

[Google Cloud security bulletins](https://cloud.google.com/support/bulletins/) · [PHP 8 changelog](https://www.php.net/ChangeLog-8.php) · [Oracle November Java advisory](https://www.oracle.com/security-alerts/cspunov2026.html)

### Catch-up — Ubisoft turns its generative-gameplay team into a subsidiary

**Actual announcement date: November 20.** Ubisoft established Motherbrain, the team behind the playable generative-AI experiment Teammates, as a dedicated subsidiary. Its stated focus is smart NPCs with memory and AI game masters that coordinate large systemic worlds. Ubisoft says the unit may serve both its own Creative Houses and external creators.

## Open source & developer tools

### Action radar — Claude Code 2.1.330 protects parallel sessions

Claude Code 2.1.330 fixes several failures that matter when the terminal agent is used concurrently: exiting a worktree could delete it while another session was still using it, simultaneous saves could lose user settings, resumed sessions could open empty or fail, and MCP servers declared by subagents could shut down while still in use. Anthropic also says it fixed long stalls after context compaction or `WebFetch`.

**Why it matters:** this is a practical stability release for worktree-heavy or multi-session workflows, not a new capability benchmark. If those patterns are part of your setup, the useful check is to resume two sessions in separate worktrees and confirm that settings and shared MCP connections survive normal exits.

[Official Claude Code 2.1.330 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.330)

### Action radar — browser-use 1.0.7 makes long MCP browser jobs recoverable

browser-use 1.0.7 changes how long `browser_exec` calls behave through its MCP server. Instead of timing out at 60 seconds, a call returns the output produced so far by 50 seconds while the cell continues running; a later empty call retrieves the remaining output.

**Why it matters:** orchestration clients can keep a long browser task alive, but the first response may be partial rather than proof of completion. A sensible pilot is one read-only job that routinely exceeds a minute, then an empty follow-up call to collect the rest of the same running cell's output.

[Official browser-use 1.0.7 release](https://github.com/browser-use/browser-use/releases/tag/1.0.7)

### In development — Codex docks the Agent Command Center beside the conversation

Two November 21 commits add a wide-terminal workspace in which the Agent Command Center stays docked next to the transcript. A follow-up makes it reachable with `leader a` and lets pane-navigation shortcuts move between the task list and conversation. The change is behind the `tui_workspace` feature and is not yet a stable release promise, but it points toward supervising multiple tasks without leaving the active conversation.

[Docked Command Center commit](https://github.com/openai/codex/commit/1731314b3b7ec68d6b831591107958da72d61101) · [Navigation follow-up](https://github.com/openai/codex/commit/a0436d69ffd9a6d943d9b56175ba2968c5e698af)

### Recent discovery — Pi Bot packages a local multi-agent desktop team

**Repository created November 21.** [w01fb0ss/PiBot](https://github.com/w01fb0ss/PiBot) is a new Apache-2.0 desktop application built on the pi agent kernel. It combines named agents, direct and group chats, filesystem work, browser and computer use, MCP connections, routines, approvals and audit logs across macOS, Windows, Linux and Android.

The useful distinction is operational: every risky tool call passes through one policy engine, agents work in user-selected folders, and the project documents outbound connections. Its “local-first” claim still allows prompts to reach the model provider a user selects, and phone, relay or remote-runner features add their own network surface. The repository was newly created and had 145 stars when checked; that is a current snapshot, not a proven long-term adoption trend.

### Worth studying — agent-mcts brings tree search to coding agents, with negative results included

[`natsu0529/agent-mcts`](https://github.com/natsu0529/agent-mcts) wraps a coding-agent CLI with Monte Carlo Tree Search. Each branch gets its own git worktree and agent session; tests and an optional LLM judge score attempts; the best branch can be reviewed and squash-applied. Claude Code is verified, while the Codex adapter has only been tested against a fake binary.

The project is unusually candid about results. On its current two-task benchmark, tests-only search was usually no better than the first attempt, while judge-assisted search improved four runs, preserved four and worsened two. The judge cost roughly five times the wall time and still ranked the better of two passing attempts only 38 times out of 62. That makes v0.3 more useful as a research harness than as a default productivity upgrade.

### Catch-up — Errilo Auto-fix separates read-only diagnosis from PR creation

**Repository created November 19.** [`geterrilo/autofix`](https://github.com/geterrilo/autofix) connects a production-error report to a GitHub Actions workflow: an agent decides whether to act, reproduces the issue with a failing test, prepares a fix, exports a patch and opens a pull request.

Its most reusable design choice is credential separation. The agent runs in a read-only job and exports commits as a patch; a separate write-capable job creates the branch and PR, so the model process never holds a token that can write to the repository. The current integration is small and tied to Errilo plus an agent account, so it is better viewed as a pattern and a narrow workflow than a general autonomous remediation platform.

[Repository](https://github.com/geterrilo/autofix) · [Security design](https://github.com/geterrilo/autofix/blob/main/docs/security.md)

## Business opportunity

### A migration checker for task systems and agent automations

**Observed need:** Microsoft's To Do retirement creates a long transition in which work/school users move toward Planner, personal users need a different application, existing tasks do not automatically migrate into the new private plan, and API retirement dates remain separate.

**Product hypothesis:** a small export-and-audit tool could inventory lists, reminders, recurrence, shared tasks and integrations; map them to Planner or another destination; and produce a dry-run reconciliation report before any write. A paid service could add migration playbooks for small teams and verification after cutover.

**Small validation:** interview five heavy To Do users and manually audit one exported account, measuring which semantics cannot round-trip. **Risk:** Microsoft may release better first-party tooling, APIs may change, and handling personal task data requires strong privacy and deletion guarantees.

[Microsoft transition guidance](https://support.microsoft.com/en-us/planner/to-do-to-planner) · 2026-11-18
