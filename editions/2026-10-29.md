## Key points

1. **GitHub Universe connects models, runtime, workflows and security—not just another Copilot client.** Copilot Fusion is generally available and selects/combines models by task. Experimental local-model routing still makes routing decisions in the cloud; it is not offline development.

2. **Competition is shifting from individual models to harnesses and learning workflows.** Microsoft's GitHub-built Copilot harness enters Foundry public preview. GitHub Memory is generally available; Automations can propose changes from label reversals, accepted comments and merged PRs, but every self-change still needs human review.

3. **Deeper automation makes supply-chain and permission boundaries more important.** Agentic Workflows launches with read-only defaults and sandbox execution; Actions lockfiles become generally available. AWS compute pools also require updated network allowlists, or a resilience improvement may cause connection failures.

## Tech & AI

### [Copilot Fusion brings multi-model orchestration into the default workflow](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/)

GitHub announced general availability October 28. Fusion combines Project HydraFusion orchestration with Auto model selection: users choose Standard, High or Max effort, and the system selects one or multiple models. GitHub reports a Fusion Max score of 60 on the Artificial Analysis Coding Agent Index—two points from Claude Code + Opus 5.5 Max—with roughly half the average API cost/tokens and 40% less task time. These vendor-disclosed benchmark results do not guarantee the same gains in every repository. Billing still reflects each model actually called, and current discounts are temporary.

[Local-model routing](https://github.blog/changelog/2026-10-28-github-copilot-fusion-now-supports-selection-of-local-models/) enters experimental preview. Supported Windows devices can use Windows ML-managed MAI Code 1.1 Flash; the CLI on Windows, macOS and Linux can connect to local OpenAI-compatible services running MAI Code 1.1 Flash or Qwen3.8 Flash Next. **Routing still happens in the cloud.** Local inference is not an offline session, and local-model safeguards may differ. Test fixed tasks for quality, total cost, cloud-call share and failure fallback rather than judging privacy/value from the “local” label.

### [Microsoft's Copilot harness in Foundry makes the runtime a separate product layer](https://devblogs.microsoft.com/foundry/microsoft-copilot-harness-in-foundry/)

The harness surrounds the model and manages context, tool calls, files/sandboxes, long-task loops, model selection and governance. Microsoft says Copilot Code, Copilot Studio, GitHub Copilot app/CLI and VS Code use it; it now enters Foundry Agent Service public preview. Developers supply instructions, Skills, tools and models while Microsoft runs the loop and sandbox. Foundry supports reusable Skills, MCP tools, constrained subtask delegation and source-controlled agent definitions. Long-running managed-agent resilience is generally available.

This changes the build-versus-buy decision, not proof that a managed harness is better. Microsoft says its runtime moved to Rust and optimizes time to first token/session overhead across 20-plus frontier models and bring-your-own-key setups. Public evidence remains mainly vendor performance/scale descriptions, without independent comparisons by task, model, region and price. Small teams can compare the same task on their existing framework and Foundry for observability, permissions, recovery, cost and lock-in before deciding migration scope.

### [GitHub Intelligence and Automations: memory launches, self-improvement keeps human review](https://github.blog/changelog/2026-10-28-github-intelligence-puts-your-code-context-and-history-to-work/)

Copilot Memory is generally available on paid plans, carrying personal preferences/repository conventions across app, CLI, VS Code, cloud agents, code review, Slack, Teams and Mobile. Users can inspect/delete personal memories. Dreaming remains an opt-in public preview that organizes memory and proposes repository Skill, instruction or review-rule changes through PRs; it consumes AI credits. GitHub reports preview CLI sessions using Memory were 93% more aligned with preferences and 42% more efficient. These are platform-attributed results for particular sessions, not universal benefits.

[Automations' self-improvement](https://github.blog/changelog/2026-10-28-copilot-automations-now-learn-from-outcomes-and-self-improve/) observes real GitHub outcomes—reverted labels, accepted comments, merged PRs—and proposes prompt, tool or trigger changes. Every change needs human approval before application. This is more useful than a simple run-success count, but acceptance/merging also reflects timing, permissions and team habits. Begin with bounded triage/review tasks and measurable outcomes; track false positives, human reversals, cost and misses together rather than optimizing one easily inflated metric.

### [Agentic Workflows compiles natural-language tasks into Actions](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/)

The open-source `gh aw` project compiles Markdown descriptions of issue triage, CI-failure analysis, documentation updates or test writing into standard Actions YAML, using Copilot or another coding agent. General availability includes Actions Runner Controller, Docker-in-Docker, per-workflow model/routing choices, `gh aw forecast` budget forecasts and micro-VM/enclave isolation.

**Safety matters more than natural-language CI syntax.** Agents default to read-only sandbox containers, with content-integrity filters, Agent Workflow Firewall, safe-output validation and threat detection. The default Copilot CLI engine still requires a license; AI credits, third-party permissions and generated-change review costs remain. Start with read-only reports, verify logs/permissions/fallbacks, then gradually permit writes or PRs.

### Security and infrastructure

- [AI application code scanning enters public preview](https://github.blog/changelog/2026-10-28-code-scanning-for-ai-applications-in-public-preview/): CodeQL flags indirect prompt injection, sensitive-data leaks and excessive agency in PRs. It currently requires enabled scanning and GitHub Advanced Security on [github.com](http://github.com/); Enterprise Server is unsupported. Suspicious-flow detection does not replace runtime permissions, red teaming or architectural review.

- [AI Scan covers whole repositories](https://github.blog/changelog/2026-10-28-ai-scan-for-repositories-in-public-preview/): an agent scans within a fixed time budget for issues beyond CodeQL/rule coverage, using the same alert queue. A rescan after merging a fix is required to close an alert. Private organization repositories need Code Security or Advanced Security, and scans consume Code Security AI credits.

- [Actions workflow lockfiles become generally available](https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/): `.github/workflows/actions.lock` pins Actions, transitive dependencies and reusable workflows to exact commits while YAML retains readable tags/branches. Dependabot updates the lockfile. This prevents silent reference drift, not unsafe dependencies. It is a substantive advance from the October 15 preview.

- [Actions adds multicloud compute](https://github.blog/changelog/2026-10-28-github-actions-adds-multi-cloud-compute-to-improve-reliability/): eligible 2/4-core Linux jobs may run on AWS instead of Azure. Free/Pro/Team are enabled automatically; Enterprise Cloud can opt in. Teams depending on Azure IPs or Microsoft Entra conditional access must sync the complete Actions ranges from GitHub `GET /meta` to avoid authentication/network failures.

### Other updates

- [OpenAI expands ServiceNow integration](https://openai.com/index/openai-servicenow-partnership-expansion/): the ServiceNow MCP plugin is in the OpenAI marketplace. ChatGPT can find similar incidents, assess changes and update records within Action Fabric permissions. Deeper security-investigation, application-development and Codex integration remains scheduled for 2027; roadmap items are not current features.

- [Google adds an Agents CLI evaluation loop](https://developers.googleblog.com/en/hill-climbing-agent-quality-with-agents-cli-evaluation/): `eval` covers data generation, scoring, comparison, analysis and optimization, with overnight scheduling. GEPA optimization currently supports ADK, not LangChain. Google warns that averages hide individual failures and repeated tuning can overfit. Begin with a fixed set of real failures and inspect per-case regressions, not only the mean.

## Open source and developer tools

### [1 | VS Code 1.144 stabilizes Agent Host, cross-client continuity and permissions](https://code.visualstudio.com/updates/v1_144)

Released October 28, VS Code 1.144 puts platform announcements into the editor: an independent Agent Host keeps local/remote sessions running without the editor window; Agent Host Protocol 1.0 is public with libraries in six languages; sessions continue across VS Code, Copilot CLI, GitHub Copilot App and [github.com](http://github.com/). New sessions default to Copilot harness, with Claude Code or OpenAI Codex harness choices through a Copilot subscription. Cloud sessions/automations require paid Copilot and follow organization policies; uncommitted local changes do not automatically enter cloud workspaces.

First test one existing task's continuity between local, remote and another client, then compare harness results—rather than enabling every preview at once. Model comparison can now start without a repository or with an empty one, and working sets allow keeping/reverting edits per file. Assisted permissions is generally available but relies on model risk judgments; uncertain/high-risk calls still require confirmation. Computer Use remains experimental, limited to local macOS/Windows Copilot-harness sessions. Limit applications, directories and credentials before enabling it.

### [2 | Qwen Code 0.26.3 adds persistent Workflow mode and ACP identity](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.3)

QwenLM released 0.26.3 stable October 28. Workflow mode can be enabled and persisted through CLI, SDK or ACP. Generated UI cards retain inputs/state across navigation, session switches and split views, but are offered only to clients supporting MCP Apps—interactive interfaces returned by MCP tools. Tool results shrink according to space left before automatic compaction. ACP/daemon preserves the same fallback-node identifier across retry, cancellation, checkpoint recovery and notifications; SDK frames preserve subagent identity, reducing transcript/tool-record misalignment after recovery.

The benefit is long-session and multiclient coordination, not just UI polish. Use a task with subagents, cancellation and recovery to check transcript continuity and unnecessary compaction when comparing ACP agents. A safety fix also stops `/autofix-pr start` if the PR branch has unpushed commits or uncommitted changes, protecting otherwise invisible work from the watcher. It reduces one risk but does not remove the need for diffs, tests and human review.

### [3 | Zed 1.26.2 improves external-agent sessions, macOS and debugging](https://github.com/zed-industries/zed/releases/tag/v1.26.2)

Released October 28, Zed 1.26.2 applies ACP configuration defaults only to new sessions, preserving reopened sessions' settings. External-agent model/configuration pickers gain better fuzzy search; OpenCode compatibility improves for DeepSeek reasoning and disabling Google-model thinking. Fixes address hangs restoring subagent sessions, authentication overwriting drafts and duplicated reasoning from OpenAI-compatible providers.

For macOS users running Codex, Claude Code or OpenCode through Zed, treat this as a stability regression check rather than a migration decision: reopen an old ACP session and verify settings, drafts, reasoning and subagent history. Other additions include optional Pyrefly Python language-server support, expandable debugger-variable hover trees, WebAssembly DWARF debugging and macOS Display P3 settings. These are official release facts; validate their value in your own repository.

### [New | GitHub Replica turns team design systems into interactive prototypes](https://github.com/github/replica)

GitHub Design released MIT-licensed Replica October 28. Designers organize components, patterns and documentation into team guidance; product, design and engineering then generate/iterate interactive prototypes in the Copilot app using natural language. Local prototypes need no server. An optional self-hosted Replica Hub supports publishing, comments and collaboration; GitHub does not host it.

Its value is not replacing Figma, but making design constraints executable so nondesigners can test flows and assumptions before implementation. GitHub login is required, and the documented canvas workflow depends on Copilot app. Without a Copilot plan, users can bring a model, but still maintain component guidance, prototype repositories and the optional Hub. Test one low-risk form/settings page for fidelity to actual components, states and copy. Do not treat prototypes as production-ready code.

### [Recently popular | Why a small AI Design Skills repository drew attention](https://github.com/elayadesign/ai-design-skills)

`elayadesign/ai-design-skills` ranked near the top of the October 28 GitHub Trending daily snapshot, showing about 1,395 new stars. That is a dated attention signal, not long-term rank or product quality. The small MIT-licensed repository provides portable Skills for Claude Code, Cursor, Codex and Windsurf, covering landing-page structure, conversion copy, visual systems and design-to-motion work. Its appeal is reusable aesthetic guidance rather than agent lock-in.

Maintenance/commit depth is much smaller than the star count. The Skill intervenes broadly in web tasks; global installation could override project branding, accessibility or engineering constraints. Enable it only at project level on a disposable page, compare the same brief with/without it, and manually inspect responsiveness, semantic HTML, accessibility, factuality and generic styling. This issue does not repeat recent coverage of Hallmark, Impeccable, OpenBot, ThinkRail or Cindy.

## Business Opportunities

### Agent workflow evaluation and feedback loops for small teams

**Evidence:** GitHub Automations proposes improvements from label reversals, accepted comments and merged PRs; Google Agents CLI combines generation, scoring, comparison, analysis and optimization. **Business hypothesis:** teams building automation may lack stable benchmarks, regression reports and review rules. They may pay for proof of improvement without missed critical work rather than more prompt templates.

A fixed-price starter service could use 20–50 historical tasks, per-case pass criteria and a dashboard of false positives/misses/human reversals/cost, then add weekly regression to existing GitHub automation or agent CLIs. Validate with five teams using automated issue triage or code review: can they show comparable evidence before/after their last prompt change? Risks include treating merged output as correct and overfitting old tasks for better scores.

### Reviewable AI prototyping from existing design systems

**Evidence:** GitHub open-sourced Replica while design Skills appeared together in Trending, showing interest in less generic coding-agent output. **Business hypothesis:** small SaaS/internal-product teams may need component libraries, copy rules, branding and acceptance criteria converted into agent guidance and connected to existing review—not another prototyping platform.

Offer a one-week package for one real flow: project-level Skills or Replica guidance covering design tokens, component examples, empty/error/loading states and accessibility, plus a commentable prototype and difference list. Validate using the same requirement with a generic coding agent and a constrained workflow; ask three designers/frontend developers to blind-review required changes. Risks are incomplete customer design systems, prototypes mistaken for production code and GitHub/Copilot lock-in.
