## Today in 90 seconds

- **A2UI 1.0 gives agents a stable, open way to return interactive interfaces instead of text walls.** Agents send declarative UI data; the host renders only approved native components. The first stable release includes renderer SDKs for React, Angular, Lit, Flutter and SwiftUI, with Jetpack Compose still on 0.9.1, plus agent SDKs for Python, TypeScript and Dart. It also connects to MCP Apps. This is a meaningful interoperability step, but the host still owns authentication, data validation and component policy.

- **Security teams should not treat “restricted scripting” as a hard boundary.** Plone disclosed a chain that lets an anonymous visitor escape restricted code and reach server execution across supported 6.x releases and older versions back to at least 4.3. Fixed releases and a cross-version hotfix are available. Barracuda also confirmed limited exploitation of a separate ESG authentication-bypass/command-injection chain.

- **Agent infrastructure is separating into portable UI, execution isolation and code security.** OpenShell moved into CNCF Sandbox under neutral governance; Codex Security shipped a 0.9.1 CLI/SDK update; and several practical projects surfaced around private meeting notes, agent-controlled creative tools and static recompilation.

## Tech & AI

### Action radar — Gemini Decisions API adds a low-latency control plane

Google introduced the Gemini Decisions API, powered by `gemini-decision-1`, for closed-set choices rather than free-form generation. One request can apply up to 1,000 yes/no, multiple-choice or ordered-rubric questions to a shared text, image, audio, video or PDF input, returning probabilities and confidence scores. Google documents inputs up to 256K tokens and prices the service at $0.10 per million input tokens with no output-token charge.

**This is worth learning because it separates routing and policy gates from the slower model doing the main work.** A useful first experiment is a narrow, reversible gate—such as selecting a model tier or deciding whether context needs human review—while logging probabilities and retaining a fallback. Google's 150–250 ms latency, calibration and cost comparisons come from its own benchmarks; the published comparison describes contexts up to 16K tokens even though the API limit is higher. They are not independent proof for a particular workload, and a probabilistic score should not become the sole control for a high-stakes action.

[Google announcement and examples](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)

### A2UI 1.0 makes generative interfaces portable

Google released the first stable version of [A2UI](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/) on November 11. Instead of asking a model to emit arbitrary application code, an agent describes a UI as structured data. The receiving application maps that data onto its own registered components and design system. That makes an agent-built form, approval screen or chart portable across first-party apps and hosts such as MCP Apps while keeping rendering native.

The 1.0 surface includes open renderer SDKs for React, Angular, Lit, Flutter and SwiftUI, agent SDKs for Python, TypeScript and Dart, bidirectional function calls, accessible components, extensions and secure data binding. Jetpack Compose remains at 0.9.1, with its 1.0 release still pending. Google says Atlassian, Alation, Bloomberg and ByteDance are building with the protocol; that is vendor-reported adoption, not an independent deployment audit.

Why it matters: A2UI creates a credible common layer between “agent intent” and a product’s real component library. It reduces the need to ship model-generated executable UI code and gives the host a policy boundary. It does **not** remove application security work: the host still decides which components and actions exist, validates data and permissions, and protects backend operations.

Try the official no-install [A2UI Composer demo](https://a2ui-project.github.io/composer/) or inspect the [Apache-licensed repository](https://github.com/a2ui-project/a2ui).

### Catch-up — Plone fixes an anonymous remote-code-execution chain

*Actual disclosure: November 10; included now because the detailed oss-security notice entered this report window and the previous brief missed it.*

The [Plone/Zope Security Team](https://community.plone.org/t/plone-security-hotfix-20261110/23313) disclosed a chain involving missing security declarations, overly broad module exposure to restricted code and a REST API permission bypass. Together, the issues let an anonymous visitor escape the restricted scripting environment and execute server code. Supported Plone 6.0, 6.1 and 6.2 are affected, and the team says older versions are affected back to at least 4.3.

Fixed full releases are Plone 6.0.16, 6.1.6 and 6.2.3. The team also published `Products.PloneHotfix20261110` for Plone 4.3 through 6.2 and recommends restarting Zope after installation. At publication time the advisory did not list assigned CVEs. The important lesson is broader than Plone: an application sandbox is only as strong as every object and module exposed to it.

### Catch-up — OpenShell moves into CNCF Sandbox

*Actual announcement: November 10; included because it was absent from the previous brief.*

NVIDIA donated [OpenShell to CNCF Sandbox](https://www.cncf.io/blog/2026/11/10/welcoming-openshell-to-the-cncf-open-governance-to-secure-agentic-ai/) and the project is moving from NVIDIA’s GitHub organization to the neutral `ai-openshell` organization. OpenShell uses deterministic policy enforcement, including Cedar policies, to constrain agent access to network, filesystem and other host capabilities.

CNCF explicitly describes Sandbox projects as experimental and identifies unfinished work: broader isolation and platform coverage, security review, observability, packaging, SBOM/signing and multi-tenancy. The governance move is useful because execution isolation needs cross-vendor scrutiny, but it is not a production-readiness certification.

## Open source & developer tools

### Action radar — Qwen Code 1.0 Preview becomes a native cross-platform agent

Qwen Code 1.0 Preview combines the agent capabilities of Qoder and Qwen Code for code understanding, implementation, debugging and testing. The concrete workflow change is distribution: it now provides native macOS, Linux and Windows packages without requiring a separate Node.js installation, while retaining multiple model providers, custom compatible endpoints, session resumption and non-interactive execution.

**Try it only as a separate preview evaluation, not as an automatic migration.** On macOS, compare startup, session resume and one scripted run against the current 0.27.x workflow on a disposable repository. The release explicitly warns that interfaces, configuration and behavior may change, and it provides no migration guide or independent reliability benchmark.

[Qwen Code 1.0 Preview release](https://github.com/QwenLM/qwen-code/releases/tag/v1.0.0-preview)

### Action radar — Gemini CLI 0.68.0 tightens extensions, hooks and container sandboxes

Gemini CLI 0.68.0 adds an extension-validation command and serializes concurrent installs with a per-extension lock. It also maps the `SubagentStop` hook, preserves the selected model across transient fallback, cancellation and rewind, resolves symlinked glob paths canonically, waits for history replay before ACP session loading, and supplies `--userns=keep-id` to rootless Podman sandboxes.

**This is most useful if you rely on extensions, lifecycle hooks or rootless containers.** Validate an extension and run one subagent-stop and Podman ownership test before changing a shared workflow. These are verified release-note changes, but the notes do not amount to a security audit of extensions or the sandbox.

[Gemini CLI 0.68.0 release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.68.0)

### Recent discovery — FrigadeHQ/yogurt

*Active/public attention: November 11.*

[Yogurt](https://github.com/FrigadeHQ/yogurt) is a desktop meeting recorder that works without a bot joining the call. Its stated design keeps recording, transcription and summaries on the device and exposes a local MCP server for querying notes. The supported binaries target macOS 14.4 on Apple Silicon, Windows 10 x64 and Ubuntu 22.04 x64, with 8 GB RAM listed as a baseline.

This is interesting because it treats private meeting memory as a local developer primitive instead of a cloud SaaS. The practical checks are straightforward: confirm the downloaded build, storage locations, model/runtime behavior and resource use on your own machine before trusting the privacy claim for sensitive meetings. The project is MIT-licensed.

### Recent discovery — klad-app/klad

*First public release and Show HN attention: November 11.*

[Klad](https://github.com/klad-app/klad) is a 2D painting and animation application designed so a human and a coding agent can manipulate the same canvas. Its CLI exposes brushes, layers, selections and animation timelines; edits remain structured and editable rather than becoming a flattened model-generated image.

The unusual part is the shared control surface: an agent can perform precise, repeatable drawing operations while the artist keeps normal visual editing tools. It is early software. The repository says macOS pen pressure works, Linux starts with mouse support, and Windows is unproven. The application is source-available rather than open source: personal use and companies below €500,000 annual revenue are allowed under its license, while the skills and file format are MIT-licensed.

### Recent catch-up — adrbn/bo2-mac

*Beta dated November 3; first releases November 5–6; surfaced again on November 11.*

[bo2-mac](https://github.com/adrbn/bo2-mac) statically recompiles the 32-bit Windows build of *Call of Duty: Black Ops II* into native ARM64 macOS code. It uses Remill and LLVM 17, a handwritten Win32 compatibility runtime and a Direct3D 11-to-Metal layer. It does not ship the game or use Wine; users build from their own Steam copy.

For reverse-engineering work, it is a concrete example of static recompilation moving beyond older console binaries into a large x86 Windows title. It is still beta and measured primarily on M1 hardware. Users must own the game, built applications cannot be redistributed, and the project is unofficial.

### Recent release — openai/codex-security 0.9.1

*Release date: November 10; included as a recent tool update rather than same-window news.*

[Codex Security](https://github.com/openai/codex-security) provides a TypeScript SDK, CLI and GitHub Action for repository and change scans, finding validation, patch generation, threat models and SARIF/JSON/CSV output. Version 0.9.1 adds breaking naming and manifest-path changes, including `coverage` becoming `review`, and keeps external scanner imports enabled by default.

The useful entry point is a read-only scan on a small repository, followed by manual validation of a few high-confidence findings. The main constraint is operational: local scanners run with the host process’s permissions and may inherit environment credentials. Use a constrained environment and remove unrelated secrets before evaluation. The release requires Node 22.13+ (or supported 24/26) and Python 3.10+.

### Worth researching — tokio-rs/topcoat

*Originally announced July 22; included because it re-entered current Trending and had not appeared in the recent briefs.*

[Topcoat](https://github.com/tokio-rs/topcoat) is an experimental full-stack Rust web framework. It server-renders markup, translates selected type-checked Rust expressions into JavaScript for instant client reactivity without a WASM bundle or separate client build, and uses server-rendered “shards” for interactions that need fresh server data. It also includes module-based routing, editable UI components and asset tooling.

The design is appealing for Rust teams that want one language and a server-first model, but the repository explicitly warns that it is early and breaking changes should be expected. It is a research candidate, not a migration recommendation.

## Business opportunities

### 1. A2UI compatibility and safety test kit

**Observed demand signal:** A2UI 1.0 now spans several renderers, agent SDKs and MCP Apps, while hosts remain responsible for catalog policy, action authorization and data validation.

**Hypothesis:** A small team could sell a CI tool and hosted report that replays A2UI fixtures across renderers, checks schema compatibility and accessibility, and flags unsafe actions or unsupported components. A low-cost validation would be to publish an open fixture pack for three common workflows—approval, comparison and editable form—and interview five teams integrating A2UI or MCP Apps. The risk is rapid protocol evolution and platform vendors adding equivalent tooling.

### 2. Constrained agent-security evaluation for small engineering teams

**Observed demand signal:** OpenShell is formalizing execution isolation, while Codex Security exposes programmable repository scanning and Plone’s incident shows how composable permission gaps can become code execution.

**Hypothesis:** Offer a fixed-price, read-only “agent security readiness” assessment: map tool permissions, run a constrained code scan, review secret exposure and produce a minimal policy baseline. Validate it with one open-source repository and one consenting small team before building automation. Risks include false positives, sensitive source access, liability and quickly changing platform controls.
