## Key points

- **OpenAI is turning grid flexibility into a public condition for future compute campuses.** Its new Grid Protectors Program promises demand reduction during grid stress, storage or on-site generation where appropriate, and project-specific infrastructure funding. The Georgia model is still in development, so the headline numbers remain company estimates rather than independently verified operating results.

- **LongCat-2.5 moved from preview to the public API, while a new security paper shows why agent runtime controls still matter.** LongCat says the model combines native multimodal input with long-horizon coding and supports common harnesses. Separately, a preprint demonstrates that poisoned pretraining data can survive clean post-training and trigger command execution in small CLI agents.

- **Developer tooling is filling in the operational layer around agents.** Paperclip manages multi-agent goals, budgets and approvals; Worktrunk makes parallel Git worktrees easier; colibri and FreeToken pursue local inference for large MoE models. All are promising, but each shifts meaningful security, hardware or operational responsibility to the user.

## Tech & AI

### [OpenAI launches the Grid Protectors Program](https://openai.com/index/grid-protectors-program/)

OpenAI announced the program on November 2. It says future compute campuses will be designed with utilities, regulators and policymakers so they can reduce demand when the grid is under strain. Depending on the site, the package may include flexible load, battery storage, on-site generation and funding for generation or transmission infrastructure. OpenAI also says households and small businesses should not subsidize the energy and infrastructure costs caused by its campuses.

The first named model is a planned Georgia campus. OpenAI says it could eventually provide up to 1,000 MW of demand response—roughly the demand of 700,000 homes by the company's estimate. The project is still in development, and flexibility cannot replace all new generation and transmission. The important change is therefore a public operating commitment, not proven grid performance.

For infrastructure teams, the questions worth tracking are concrete: who controls curtailment, what service level is guaranteed during grid events, who pays for interconnection upgrades, and whether load-reduction claims are independently metered.

### [LongCat-2.5 becomes available through the LongCat API](https://longcat.chat/platform/docs/ChangeLog.html)

LongCat's official changelog marks November 2 as the general API availability date for LongCat-2.5. The provider describes three practical focuses: native multimodal input for visual coding and creative or 3D tasks; long-horizon reasoning and tool use across complex codebases; and compatibility with Claude Code, Codex, Hermes and other agent harnesses.

This is the first clear date-backed move from the September preview into a service developers can call. The claims about capability and long-horizon performance come from the provider; this brief did not independently benchmark the model. A useful evaluation would test one repository task that genuinely needs image context and several tool calls, then compare completion quality, latency, cost and failure recovery against the model already in use.

### Catch-up · [Agentic backdoors can survive clean post-training](https://arxiv.org/abs/2610.37741)

A preprint submitted October 27 studies whether malicious content inserted into pretraining data can become a command-execution backdoor in a deployed agent. The authors trained Qwen3-family models from scratch at 0.6B, 1.7B and 4B parameters, then used a clean pipeline to turn them into CLI agents. With 0.1% poisoned pretraining data, the 4B model reached roughly 92% attack success in the tested trigger setting while behaving normally on clean inputs. The paper reports non-zero effects at a much lower poison rate as well.

The result is important because clean supervised fine-tuning, preference tuning and reinforcement learning did not reliably erase the planted behavior. But the boundary matters: this is a preprint and a controlled experiment on models up to 4B parameters, not evidence that a particular production model is compromised or that the same rate applies at frontier scale.

The practical implication is architectural. Training-data provenance helps, but agent products still need runtime containment: least-privilege tools, sandboxing, explicit confirmation for risky commands, auditable action traces and detection focused on actions rather than only final text.

### Security watch · [CrewAI SSRF advisory needs a verified affected range](https://github.com/advisories/GHSA-x35j-64g3-fxg7)

GitHub's advisory feed published GHSA-x35j-64g3-fxg7 on November 2. Its summary says CrewAI's SSRF guard and HTTP client can inspect different URL representations, allowing a malicious URL to bypass the guard and reach tools such as `ScrapeWebsiteTool`.

The advisory page could not be independently opened during this run, so the affected versions and fixed version were not confirmed. Treat this as an observation to verify against the advisory and CrewAI's own release notes—not as a blanket instruction to upgrade to a guessed version. If CrewAI tools can fetch user-controlled URLs, the immediate design check is whether outbound access is constrained independently of application-level URL validation.

### Catch-up · [Tor Browser 16.0 completes its Firefox ESR transition](https://blog.torproject.org/new-release-tor-browser-160/)

Released October 29, Tor Browser 16.0 is the first stable version based on Firefox ESR 153. The Tor Project says its annual transition audit covered more than 270 Firefox changes with possible privacy or security effects. The release redesigns settings, adds an opt-in generic-window-title mode to reduce browsing-history leakage to other desktop software, adds stable Linux ARM64 support and ends 32-bit x86 Linux support.

Generic titles are intentionally opt-in because the project has not fully evaluated accessibility and desktop-environment side effects. Existing preferences should carry forward, but users on unusual window managers or assistive technology should treat the option as a compatibility test rather than an automatic privacy win.

## Open source & developer tools

### Updated · [Codex can recover WebSocket transport after a transient fallback](https://github.com/openai/codex/commit/0a2dda4b5e748a2ba135c87f6f6de19f05498dd4)

A November 2 Codex commit changes a session-level failure mode. Previously, one transient WebSocket failure could leave the rest of the session on HTTP. The new logic probes WebSocket connectivity in the background while current HTTP requests continue, lets a later request take over a recovered connection, caps the first-response wait for a recovery probe at five seconds and respects `Retry-After`. HTTP 426 responses keep the session on HTTP, and retries of an existing HTTP request do not jump transports mid-request.

This is a verified source commit, not yet proof that every distributed Codex build contains the change. The value is operational rather than flashy: long sessions should recover low-latency transport without sacrificing the conservative HTTP fallback.

### Recently popular · [Paperclip adds governance to multi-agent work](https://github.com/paperclipai/paperclip)

Paperclip appeared in the November 2 GitHub daily Trending snapshot with 451 stars attributed to that snapshot. It is an open-source Node.js server and React UI for coordinating multiple agents around goals, tasks, org roles, budgets, approvals and run history. Adapters cover several agent runtimes and model providers; the system can enforce budget limits, pause agents and preserve a central view of work and cost.

The useful idea is not the "AI company" branding. It is a control plane that treats permissions, spend and accountability as first-class objects instead of loose prompts. The local quick start requires Node.js 24.11+, pnpm 9.15+ and, for some local Claude or Codex sign-in paths, Python and the provider CLI. Remote access should use authenticated deployment on a private network. The project is broad and fast-moving, so security boundaries and recovery behavior deserve testing before autonomous operation.

### Recently popular · [Worktrunk makes parallel agent worktrees less awkward](https://github.com/max-sixty/worktrunk)

Worktrunk appeared in the same daily snapshot with 136 stars attributed to the snapshot. The Rust CLI turns Git worktrees into branch-like operations: `wt switch`, `wt list`, `wt merge` and `wt remove`. It can start an agent in a new worktree, show CI and diff status, automate hooks and share build caches with copy-on-write filesystems.

This directly addresses a real multi-agent bottleneck: agents need isolated working directories, but plain Git worktree commands become repetitive and easy to mismanage at scale. Its hooks and automated merge flow are also where mistakes can become expensive. Start with a disposable repository, inspect generated commands and keep destructive cleanup under review until the branch and worktree conventions are familiar.

### Recent release · [colibri 2.1.0 broadens portable local MoE inference](https://github.com/JustVugg/colibri/releases/tag/v2.1.0)

colibri 2.1.0 was released on October 31 and appeared in the November 2 daily Trending snapshot with 655 stars attributed to that snapshot. The project is a pure-C runtime that streams mixture-of-experts weights from disk and supports CPU, Vulkan, CUDA and Apple Metal paths. Version 2.1.0 adds native GGUF import across its engines, prebuilt archives for Linux, Windows and Apple Silicon, and lower-memory cache defaults for several model families.

The constraint is physical, not just software. The showcased models can require hundreds of gigabytes of model storage and substantial memory bandwidth. Streaming makes very large models possible on more machines, but it does not make them small or necessarily fast. Treat author performance tables as hardware-specific measurements.

### Recently popular · [FreeToken brings a server-oriented alternative for local models](https://github.com/FlashML-org/FreeToken/releases/tag/v0.2.1)

FreeToken first appeared in the collector's daily Trending coverage on November 1 and was credited with 654 stars in the November 2 snapshot. Version 0.2.1, released October 26, adds image input for several GGUF model families and expands architecture support. It exposes OpenAI-, Anthropic- and Responses-compatible endpoints, making it easier to place a local model behind coding or tool-calling agents.

The project is currently more hardware-specific than its desktop-scale message suggests: the documented accelerated path centers on Linux x86-64, CPython 3.12 and CUDA 13, and an open issue reports a performance regression on an RTX 4060 between 0.1.3 and 0.2.0. It is worth evaluating for a dedicated inference box, not assuming it will be a drop-in improvement on every workstation.

### Upstream watch · [Codex is making its shared daemon the default path](https://github.com/openai/codex/commit/a5c409243744c3b99776259eea2f3a13d6af4447)

An official November 2 source commit removes the `features.daemon_auto_start` gate. Eligible interactive launches will start or reuse Codex's shared background server even if that setting was disabled; `--no-daemon` becomes the explicit opt-out. The change also retires managed requirements for the old flag and emits migration notices.

**Why it matters:** This changes process lifetime and the way an explicit “no background daemon” policy must be expressed. Because a shared background process may outlive the shell that launched it, proxy and environment inheritance are points to verify, not regressions demonstrated by this commit. If you rely on the current feature flag, note the migration now. When a stable release contains this commit, test `--no-daemon` in a disposable session and inspect the resulting process behavior before changing policy.

This is an unreleased main-branch change, not evidence that the installed stable build behaves this way.

## Business Opportunities

### Grid-flexibility evidence for compute campuses

**Verified signal:** OpenAI is publicly tying future campus operation to demand response, storage and infrastructure funding.

**Commercial hypothesis:** Utilities, data-center developers and local governments will need a neutral evidence layer that turns promises into interval-metered curtailment reports, event replay and cost-allocation records.

**Small validation:** Use public grid-event data to build a synthetic dashboard for one region, then interview five utility or colocation operators about the minimum evidence required to approve a flexible-load agreement.

**Risks:** Long enterprise sales, regulated procurement, integration with utility telemetry and liability if reports are treated as operational control.

### A narrow control plane for small multi-agent teams

**Verified signal:** Paperclip's trending growth and Worktrunk's adoption show interest in managing multiple concurrent agents, not only improving single-agent prompts.

**Commercial hypothesis:** Small teams may pay for a read-only layer that answers three questions across Codex, Claude Code and local agents: what is running, what changed, and what did it cost? A focused product could avoid the complexity of an entire "agent company" platform.

**Small validation:** Interview five teams already running at least five parallel agents and prototype a local dashboard from existing run logs and Git state, with no write access.

**Risks:** The market may be hype-driven, platform vendors can absorb the feature, and collecting logs or credentials expands the security scope.
