## Tech & AI

### [Claude Haiku 5.5 targets parallel subagents and real-time operations](https://www.anthropic.com/claude-haiku-5-5)

**What happened:** Anthropic positioned Haiku 5.5 for classification, summaries, context compression, browser operations, and tightly scoped subagent tasks. It was the first Haiku with adjustable reasoning effort and, according to Anthropic, the fastest Claude at standard speed. Availability included the Claude API, Claude Code, [Claude.ai](http://claude.ai/), AWS, Google Cloud, and Microsoft Azure.

For inputs up to 100,000 tokens, input/output rates were $0.10/$0.50 per million tokens; above that threshold, they rose to $0.50/$2.50. Anthropic also halved Sonnet 5.5 cache-read pricing, claiming roughly 20% lower total cost for most long-running agent tasks.

**Why it matters:** Smaller models were becoming parallel workers, context organizers, and low-cost computer-use layers, not just classifiers. Anthropic's Terminal-Bench 4 results still trailed Sonnet 5.5 substantially, favoring clearly bounded tasks over complex engineering planning.

**Assessment:** Test a layered workflow in which Opus or Sonnet plans and Haiku executes. Monitor the 100,000-token boundary in long-context work; the headline minimum price is not a sufficient cost estimate.

### [Cloudflare fixes the evidence before multi-agent security analysis](https://blog.cloudflare.com/agentic-security-operations/)

**What happened:** Cloudflare Managed Defense first uses deterministic programs to gather customer identity, historical alerts, traffic baselines, mitigation outcomes, and network observations, preserving each item's source, version, and timestamp. No model is called during this stage. A lightweight model filters obvious false positives; four specialists then investigate traffic, customer context, global telemetry, and threat intelligence in parallel. A synthesis agent produces recommendations.

The synthesis agent cannot collect new evidence and must choose from preapproved conclusion categories. Cloudflare said an earlier general-purpose agent confused alert hypotheses with facts, queried the wrong accounts or time ranges, and mistook failed queries for a clean result. Those failures prompted the layered design.

**Why it matters:** Retrieval, scope, and failure states should be enforced by code; models should handle judgment. The approach also fits code review, financial analysis, and production troubleshooting. Shared input snapshots make runs comparable and auditable.

**Assessment:** The important feature is not the number of agents. It is the separation of evidence collection and scope control from model reasoning. Copy that boundary before adding more roles.

## Open source & developer tools

### [Worth studying: Copilot's production local sandbox and open-source MXC](https://github.com/microsoft/mxc)

**What happened:** GitHub moved local sandboxing from preview to general availability across Copilot CLI, the Copilot desktop app, and VS Code sessions using Agent Host. Administrators or developers can restrict readable/writable directories, public and local networks, and Git/GitHub CLI credentials. Centrally enforced policies cannot be weakened by developers. The feature costs no extra.

Microsoft eXecution Container (MXC), the underlying MIT-licensed project, provides a common policy interface across Windows, Linux, and macOS. Depending on platform, backends include ProcessContainer, Bubblewrap, macOS Seatbelt, LXC, and experimental MicroVMs. Rust, .NET, and Node SDKs are available.

**Why it matters:** MXC turns project-directory and domain restrictions into OS-enforced boundaries rather than prompt-based promises. It can be embedded beyond Copilot, making it useful for cross-platform agent-runtime design.

**Assessment:** Start with the policy schema and Node examples. **Audit mode completely disables sandbox protection for the target workload**; use it only to analyze trusted programs, never to run unknown model-generated code.

### [GitHub introduces a purpose-built leaked-credential detection model](https://github.blog/changelog/2026-10-07-purpose-built-model-for-leaked-secret-detection/)

**What happened:** GitHub began using a specially tuned classifier to detect passwords and credentials from surrounding code even when they lack standard token formats. It does not generate code or prose. Existing AI password alerts switched automatically. Blocking suspected secrets during pushes remained in private preview; Copilot `/security-review` integration was not yet broadly available.

Existing background secret alerts remained included in GitHub Secret Protection and Advanced Security. New push checks and Copilot security reviews would consume AI Credits—even if a check ultimately allowed the push. These extra checks were off by default and required administrator activation.

**Why it matters:** Format-based and regex scanners can miss credentials such as `password = "company-summer-2026"`. Contextual models may improve detection, but add false positives, latency, and usage costs.

**Assessment:** Measure false positives on historical commits before enabling it. Set a spending limit that actually stops consumption; a budget alert alone does not stop credit charges.

### [Worth trying: Copilot CLI discovers and switches to local Ollama models](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/)

**What happened:** Starting with Copilot CLI 1.0.94-0, `/model` discovers running local Ollama models alongside GitHub-hosted and user-configured models. It does not install Ollama or download weights. Models must support streaming and tool calls. Switching applies to the current session without restarting the CLI.

GitHub warned that choosing a local model **does not enable offline mode or disable telemetry**. Set `COPILOT_OFFLINE=true` explicitly. Even then, prompts and code can leave the machine if the configured compatible endpoint is remote.

**Why it matters:** On your 48 GB 4090 machine, the same Copilot tools and workflow can compare local Qwen or DeepSeek models with cloud models without changing the entire agent harness.

**Assessment:** Use a public repository to compare tool-call success, first-token latency, and long-task stability. For privacy checks, inspect the provider address, offline variable, and outbound traffic—not merely a “Local” model label.
